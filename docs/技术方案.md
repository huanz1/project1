# 技术方案 · 实验室设备预约系统

## 1. 选型决策
| 方面 | 选择 | 理由 |
| --- | --- | --- |
| 形态 | 纯前端单页应用（SPA） + 一个零依赖 AI 代理 | 静态托管 0 成本上线（第 4 天）；AI 代理是实验七 T1 课程要求（Key 在服务端） |
| 技术 | 原生 HTML/CSS/JS | 无构建步骤，部署即复制文件，稳定性高 |
| 存储 | localStorage | 免数据库持久化，满足单机演示与数据回显（题库定位） |
| 图表 | Apache ECharts 5.5 | 功能成熟、本地化引入、文档完善（第 4 天外部能力接入） |
| **提交仓库** | **Gitee**（`git@`/https://gitee.com/huanz-007/project1） | 课程口径：push 到自己的 Gitee 仓库就算交作业；老师 `coolfun2018` 为开发者 |
| **部署** | **GitHub Pages** | Gitee Pages 已下线（官方回复"因不可抗原因，暂无恢复计划"）；GitHub Pages 免费、push 自动部署。同属附录 B"静态托管 0 元"路线 |

## 2. 数据模型（localStorage）
- `leq_equipment`：设备数组
  ```json
  { "id": "e1", "name": "3D 打印机", "icon": "🖨️", "location": "...", "desc": "..." }
  ```
- `leq_bookings`：预约数组
  ```json
  {
    "id": "b1700000000", "equipId": "e1", "equipName": "3D 打印机",
    "date": "2026-10-12", "slotId": "s1", "slotLabel": "08:00 - 10:00",
    "name": "吴辰枫", "sid": "2023xxxx", "purpose": "...",
    "createdAt": "ISO 时间", "status": "active | cancelled"
  }
  ```
- `leq_stats`：统计
  ```json
  { "pvTotal": 12, "pvDaily": { "2026-10-11": 12 }, "formSubmits": 3 }
  ```

## 3. 模块划分
- `js/data.js`：设备、时段常量与种子预约
- `js/storage.js`：`Store` 对象，封装增删改查、冲突检测、统计计数、AI 用量累计
- `js/app.js`：Tab 路由、页面渲染、模态框、表单提交、看板、CSV 导出、占用总览
- `js/ai.js`：AI 助手前端模块（调用服务端代理、五类故障兜底文案、用量统计）
- `server/server.js`：零依赖 Node AI 代理（实验七 T1：静态托管 + LLM 转发，Key 只在服务端环境变量）
- `vendor/echarts.min.js`：第三方图表库（只读，不修改）

## 4. 关键逻辑
### 冲突检测
```js
hasConflict(equipId, date, slotId) =>
  bookings.some(b => b.status==='active'
    && b.equipId===equipId && b.date===date && b.slotId===slotId)
```
预约提交与时段按钮渲染均调用该规则：占用的时段在界面上直接禁用并划线，提交时二次校验。

### 看板懒渲染
看板 Tab 默认隐藏，隐藏容器中 `echarts.init` 会得到 0 宽高。
方案：切换到看板 Tab 时才创建/更新图表（`ensureChart`），并监听窗口 resize。

### CSV 导出
字段加双引号并转义内部引号；文件头加 `\ufeff` BOM，保证 Excel 打开中文不乱码。

## 5. 部署与配置差异（本地 vs 线上）
- 分工：**Gitee 仓库 = 作业提交与巡查入口**（课程口径）；**GitHub Pages = 公网部署**（附录 B 静态托管路线；Gitee Pages 已下线，见 `docs/部署手册.md` §1）。两个远端都推，保持同步。
- 纯静态，无环境变量、无数据库连接，部署差异主要为**资源相对路径**：全部使用相对路径（`css/`、`js/`、`vendor/`），Pages 子目录下也能正确加载。
- 首次访问自动写入种子数据，保证线上打开即有真实数据可看。
- AI 功能需要 AI 代理在线（见第 6 节）：GitHub Pages 静态托管下 AI 不可用（页面明确提示），本地 `node server/server.js` 或服务器部署后可用。

## 6. AI 能力集成（第 7 天，PRD F11/F12）

### 6.1 架构：密钥只在服务端
```
浏览器（js/ai.js）
   │  POST /api/ai/weekly-report   （汇总数据，不含密钥）
   ▼
Node AI 代理（server/server.js，零依赖，读环境变量 AI_API_KEY）
   │  POST {AI_API_BASE}/chat/completions   （Authorization: Bearer Key）
   ▼
LLM 平台（火山方舟 / 阿里云百炼 / 硅基流动，均兼容 OpenAI 协议）
```
- 前端永远拿不到 Key；代理无状态，LLM 需要的业务数据由前端随请求提交（localStorage 在浏览器，服务端读不到）。
- 配置：`AI_API_KEY`（必填）、`AI_API_BASE`（默认火山方舟）、`AI_MODEL`（默认 doubao-pro-32k）、`PORT`（默认 3000）。

### 6.2 接口与失败兜底
| 端点 | 入参 | 成功返回 | 失败码 → 前端文案 |
| --- | --- | --- | --- |
| `GET /api/health` | — | `{ai:{configured}}` | 网络错 → “未检测到 AI 代理服务” |
| `POST /api/ai/weekly-report` | `summary` 汇总 JSON | `{report}` | 未配置→提示如何启动；超时→稍后重试；429→额度/限流；401/403→Key 无效 |
| `POST /api/ai/query` | `question` + `context` | `{answer}` | 同上 |
- 超时 30s（AbortController）；请求体上限 1MB；question 限 500 字。
- 前端 `AI.fallbackText(code)` 统一把人话兜底文案显示在结果区，其余功能不受影响（满足实验七 T1“失败兜底”验收）。

### 6.3 成本估算表（月度）
> 单价为示例价目（doubao-pro 档：输入 ¥0.0008/1k tokens、输出 ¥0.002/1k tokens），以平台官网实际价目为准，可在 `js/ai.js` 的 `AI.PRICES` 修改后自动重算。

| 项目 | 取值 | 说明 |
| --- | --- | --- |
| 月调用次数 | 300 次 | 按每天约 10 次（演示 + 真实使用） |
| 单次输入 token | ~900 | 周报汇总/问答上下文（设备 6 台 + 预约明细） |
| 单次输出 token | ~300 | 周报正文/问答答复 |
| 月输入成本 | 300×900÷1000×0.0008 ≈ **¥0.22** | |
| 月输出成本 | 300×300÷1000×0.002 ≈ **¥0.18** | |
| **月合计** | **≈ ¥0.40** | 各平台免费额度即可覆盖，实际成本约 0 |

结论：按此用量级成本可忽略；真正要守的是**密钥安全**与**限流兜底**，不是费用。

### 6.4 安全底线
- Key 只走环境变量（`AI_API_KEY=... node server/server.js`），不写代码、不进 Git、不进前端包。
- 万一泄露：立即在平台侧吊销重发，历史提交里的旧 Key 按已泄露处理（实验七 FAQ 要求）。
- 前端对用户输入（姓名/用途/问题）一律转义或 `textContent` 赋值，不拼 innerHTML。
