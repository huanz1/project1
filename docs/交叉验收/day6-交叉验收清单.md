## 二、缺陷与整改

### 【必须修 D1】修改日期后，已选时段残留，会误提交
- **复现步骤**：打开预约 → 选日期 A、点时段 s1 → 不提交，直接把日期改成 B → 此时 UI 无高亮，
  但内部 `selectedSlot` 仍为 s1 → 直接点提交，会把**未确认的 s1 提交到日期 B**。
- **根因**：日期 change 触发 `renderSlots` 重渲染按钮，但没有清空 `selectedSlot`，状态与 UI 不一致。
- **整改**：`renderSlots` 开头置 `selectedSlot = null`，改日期后必须重新点选。
- **验证**：改日期后 selectedSlot 为 null、无高亮。

### 【必须修 D4】首次切到数据看板，图表 series 不渲染（空白）
- **复现步骤**：打开页面（默认设备预约页）→ 首次点"数据看板" → 图表坐标轴出现，但柱子/扇区/折线不显示。
- **根因**：首次 `echarts.init` 后 `setOption` 的入场动画，其动画帧循环在初始化时机未正常启动，
  series 停留在起始值 0。坐标轴由静态绘制正常，唯独依赖动画的 series 不出现。
- **整改**：三张图表配置 `animation: false`，直接绘制最终值；图表瞬间显示，不依赖入场动画。
- **验证**：干净环境首次切看板，三图均渲染（像素检测柱状/饼图/折线均有内容，截图确认）。

### 【建议修 D2】当天到期只按日期判断，不精确到时段 —— 已修复
- 当天预约若时段已过仍显示"有效"可取消。已给时段加 `endHour`，新增 `isBookingExpired`
  按"当天 + 当前时刻 vs 时段结束"判定，数据层与视图层统一，并补 R6 固定时刻测试。

### 【建议修 D3】表单字段无长度上限 —— 评估后暂不处理
- 理由：姓名/学号/用途长度需求不一，硬性上限可能误伤正常填写；localStorage 容量充足，
  超长输入不影响功能。强行加限制属过度工程，留作已知限制。
