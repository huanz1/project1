# PRD · 实验室设备预约系统

> **需求来源（权威）**：课程「备选项目题库」第 5 题。选题不改，范围以题库原文为准：
> - 一句话：抢像打印机和示波器一样难的东西，排明白。
> - 最小闭环：设备台账 → 时段预约（**冲突检测是命门**）→ 我的预约/取消 → 到期提醒（先做页面标记，别做邮件）。
> - AI 点位：预约台账周报由 AI 生成（"本周 3 号机利用率高，5 号机全周闲置"）+ 自然语言查询"下周一下午有空闲的投影仪吗"。
> - 验收基线（题库原文）：第 6 天交叉验收时，最小闭环全部可演示 + 至少 6 条契约测试绿。本项目实际 10 条（R1–R10）。
> - 开题三查：AI 点位是真的——去掉 AI 功能这个作品就不成立；贴皮 AI 不予通过。
>
> 按附录 E，功能完成度以本 PRD 验收条款为准打分。

## 1. 背景与用户
- **目标用户**：工程训练中心 / 电子实验室需要借用设备的在校学生。
- **痛点**：3D 打印机、激光切割机等设备数量少、时段抢手；线下登记本看不到实时占用，到场才发现被占用，且易出现同一时段重复登记。
- **价值**：设备台账与占用情况一目了然，线上预约自动防冲突，减少白跑与登记纠纷。

## 2. 核心场景
1. 学生打开系统，浏览设备卡片与当前预约状态。
2. 选设备、日期、时段，填写姓名、学号、用途后提交。
3. 若所选时段已被占用，系统拒绝并提示更换。
4. 学生凭学号在「我的预约」查看，可取消未到期预约。
5. 管理视角在数据看板查看设备使用率与访问情况。

## 3. 功能需求
| 编号 | 功能 | 验收标准 |
| --- | --- | --- |
| F1 | 设备台账展示 | 至少 6 台设备，显示名称、位置、参数、预约状态 |
| F2 | 在线预约 | 填写完整信息后能提交，列表中出现该预约 |
| F3 | 冲突检测 | 同设备同日同时段第二次提交被拒绝并提示 |
| F4 | 日期校验 | 不能选择/提交早于今天的日期 |
| F5 | 我的预约查询 | 输入学号后只显示该学号的预约，按日期排序 |
| F6 | 取消预约 | 仅未到期有效预约可取消，取消后时段释放可再约 |
| F7 | 数据看板 | ECharts 正确渲染设备预约数、时段分布、访问趋势 |
| F8 | 访问统计 | 每次打开页面 PV +1，今日/累计 PV 正确 |
| F9 | 导出 CSV | 导出文件含全部字段，Excel 打开中文不乱码 |
| F10 | 到期提醒 | 今日将到期（当天且时段未结束）的有效预约，在「我的预约」中高亮标记并提示；只做页面标记，不做邮件/短信 |
| F11 | AI 台账周报 | 「AI 助手」页一键生成预约台账周报（总体情况 / 设备利用率观察 / 时段分布 / 管理建议），由 LLM 基于当前预约数据生成；密钥只在服务端，前端不接触 |
| F12 | AI 自然语言查询 | 用自然语言提问（如“明天下午有空闲的投影仪吗”），AI 仅依据系统内真实预约数据作答；AI 服务不可用时页面给出明确降级提示，不影响其余功能 |

## 4. 非目标（本期不做）
- 不做登录鉴权、支付、消息/邮件提醒（到期提醒只做页面标记——题库原话"别做邮件"）
- 不做数据库与多端数据同步（数据存本机浏览器 localStorage）
- 不做二维码签到、设备实时状态物联
- 题库"进阶（冲竞赛）"项本期不做：使用率热力图、AI 调度建议
- AI 代理 `server/server.js` 是实验七 T1 的**课程要求**（"接口封装放后端，Key 在服务端，不让前端裸调"），
  不是自选后端：它只做 LLM 转发 + 静态托管，不引框架、不建数据库、不加任何 npm 依赖；除此之外仍无后端

## 5. 成功指标
- 教师手机可通过公网地址打开页面并看到预置/真实预约数据（实验四验收口径）
- 完整走通「预约 → 冲突拒绝 → 查询 → 改期/取消 → 再约」闭环
- 看板图表数据与 localStorage 中的预约记录一致
- 最小闭环全部可演示 + 契约测试 ≥6 条全绿（实际 10 条，CI 每次 push 自动跑）
