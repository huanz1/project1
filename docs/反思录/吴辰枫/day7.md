# 第 7 天反思 · 吴辰枫（AI 能力集成）

## 今天指挥 AI 干成了什么
1. **AI 代理服务端上线**（`server/server.js`，零依赖 Node）：托管静态前端 + `/api/ai/weekly-report`、`/api/ai/query` 两个代理端点，API Key 只存在于服务端环境变量，前端浏览器零接触。
2. **两个 AI 点位按题库定义实现**（不是第 6 天计划里那个“用途填写助手”）：
   - 点位①：一键生成台账周报（总体情况/设备利用率观察/时段分布/管理建议四节，提示词限定“只依据给定数据，不编造数字”）；
   - 点位②：自然语言查询（“明天下午有空闲的投影仪吗”），上下文由前端组装真实预约数据随请求提交。
3. **失败兜底全覆盖**：未配置/超时/额度限流/Key 无效/网络不可达五种故障各有明确文案（`AI.fallbackText`），静态托管模式下 AI 页显示“不可用及原因”而不是白屏或报错。
4. **C1 挑战**：AI 用量统计页（调用量/成功失败/token/估算成本，存 localStorage）。
5. 补 PRD F10（到期提醒页面标记，“今日到期”徽标）与 F11/F12，并给 AGENTS.md 的“不接后端”开了 AI 代理这一个口子；成本估算表入技术方案；数据字典入 `docs/`；测试补到 8 条（R7 今日到期、R8 AI 用量累加），CI 加 server 语法检查。

## 卡过什么坑、怎么爬出来的
1. **最大的坑是第 6 天我自己把方向记偏了**：day6 反思写的是“第 7 天接入预约用途的智能摘要/填写助手”。今天对照题库第 5 题才发现——那是典型的“AI 贴皮”（去掉它系统照样成立），开题三查第 2 条明确不通过。**纠正动作**：回到题库原文，AI 点位必须是“台账周报生成 + 自然语言查询”，删掉原计划重做。教训：计划要写进任务板并对照题库验收，不能凭记忆排期。
2. **“不接后端”的自我约束和课程要求打架**：AGENTS.md 写了不接后端，但实验七 T1 要求“接口封装放后端（Key 在服务端）”。解法不是推翻约束，而是给约束开一个具名例外：只允许 `server/server.js` 一个零依赖脚本做 LLM 转发，并在 AGENTS.md/PRD/技术方案三处同步写明，防止以后 AI 会话再把“纯前端”当铁律把 server 删了。
3. **无状态代理拿不到浏览器数据**：localStorage 在客户端，服务端读不到。设计成前端算好汇总/上下文随 POST 提交，服务端只负责拼提示词和转发——顺便让 token 成本可控（周报只传计数+精简明细）。
