# 补写模板 · 第 1–3 天反思（待本人凭真实经历填写）

> ⚠️ 本文件只是**模板**，不是反思件本身。请按每天真实发生过的事填写，写好后**另存为 `day1.md` / `day2.md` / `day3.md`**（与本文件同目录），并删除或保留本模板均可。
> 原则：诚实 > 完整。找不到对话存档就写“当日未存档”；记不清细节就写轮廓，**不要编造具体对话**——老师按署名和内容真实性核分。

---

## day1.md 填写提示（环境就绪与项目开题，10-07/08）

- 装了什么软件（Trae CN / JDK / Maven / Node / Python），踩过什么安装坑；
- Gitee 注册与建仓：仓库名、是否把老师（coolfun2018）加为开发者、首次 push 时间；
- 电梯稿：给谁解决什么问题 / 核心功能恰好 3 个 / 凭什么做得完 / 最大风险与对策（后来定题为「实验室设备预约系统」的话，写清选题过程）；
- 对话证据：Trae 里第一个应用（三张器材卡片预约页）的会话截图/导出——找不到就写“未存档”。

## day2.md 填写提示（需求三件套与项目骨架）

- PRD / 技术方案 / 任务看板分别写了什么、AI 起草后你改了哪些地方（这就是“会提”的证据）；
- 项目骨架第一次跑起来是哪个 commit、你点了什么验证的；
- Git 分支规范：第一次开 `feat/` 分支、合并回主干的时间；
- 对话证据：让 AI 起草 PRD 的那轮会话（你的提示词原文 + 它的产出 + 你的修改）。

## day3.md 填写提示（核心功能闭环）

- 闭环是哪几条：设备台账 → 选时段预约 → 冲突检测拒绝 → 学号查询 → 取消释放（写清每条的验收动作）；
- 冲突规则是怎么定成“同设备 + 同日 + 同时段只允许一条 active”的（题库说这是命门，你第 3 天就该把它写进契约）；
- 对话证据：实现冲突检测那轮会话（含 AI 最初漏掉的边界，比如“已取消的预约算不算占用”）。

## 统一格式（与 day4+ 一致）

```markdown
# 第 N 天反思 · 吴辰枫（当天主题）

## 今天指挥 AI 干成了什么
（写具体功能和验证动作，不写“学习了新东西”）

## 卡过什么坑、怎么爬出来的
（一件事就够：AI 错在哪 → 你改了什么 → 返工结果）

## 对话证据
（提问→翻车→修正的原文，或截图文件名；没有就写“未存档”）

## 明天改进的一个动作
（具体，可执行）
```

> 补写后记得：`git add -A && git commit -m "dayN: 补写前三天反思" && git push`。
> 注意：tag 是“交卷时间戳”，补写的内容算在补写当天，不影响原有 tag 的判定；老师巡查按 commit 署名和内容质量核分。
