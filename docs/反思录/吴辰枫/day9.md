# 第 9 天反思 · 吴辰枫（冲刺收尾与路演彩排）

## 今天指挥 AI 干成了什么
1. **缺陷清零（只修影响演示的）**：机械核对 app.js 全部 38 个 `getElementById` 引用与 index.html 的 ID 一一对应（0 缺失）；复查新增代码的 XSS 面（改期标题/总览单元格/AI 结果全部走 `textContent` 或 `escapeHtml`）；确认取消/改期后总览与设备徽标实时联动。
2. **作品集四件套齐套**：线上地址（README）+ 规范仓库（README 架构图/AGENTS.md/部署手册）+ 三件套（PRD/技术方案/冲刺任务板）+ 100 字 AI 协作叙事（`docs/作品集-AI协作叙事.md`）。
3. **部署手册补第 8 节**：AI 代理三种部署路线（本机/云服务器/静态托管不可用）、三个平台的 Key 申请与 `AI_API_BASE`、启动自检命令、安全清单（Key 不进 Git）。
4. **3 分钟彩排稿 + 预判挑刺分级**（`docs/路演彩排.md`）：7 条刺分级处理，两条必修——AI 依赖（把“停 server 看兜底”设计成正式演示环节，变依赖为卖点）、github.io 网络（本地副本 + 手机真机 + 录屏三重保险）。

## 卡过什么坑、怎么爬出来的
**彩排预判时发现的最大风险不是技术，是“演示叙事”**：AI 功能现场依赖 Key 和网络，按原脚本它是“压轴戏”，挂了就冷场。化解办法是把兜底本身变成演示的一部分——讲到 AI 助手时**当场停掉 server**，让评委看到“未检测到 AI 代理服务”的明确提示和其余功能毫发无损，这反而证明了 T1 验收点“失败兜底”是真的做了。**教训：演示脚本要按“会翻车的点”设计，而不是按“功能列表”设计。**
