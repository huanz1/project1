# 第 5 天反思 · 吴辰枫（质量护栏 + CI）

## 今天的目标
给项目补齐关键业务规则测试、挂 CI、做一次 AI 评审。

## 我做了什么
1. **人工点名 5 条业务规则**（不是让 AI"给所有接口写测试"）：种子初始化、同设备同时段冲突、不同维度不冲突、取消释放、新预约落库。
2. 用 Node 内置 `node:test` + 内存版 localStorage 跑通，零依赖；`vm` 沙箱加载浏览器脚本，**不改线上代码就能测**。
3. 配 **GitHub Actions**：push 自动跑 `node --test`，徽章贴 README。
4. 用"第二个 AI"评审，发现并整改 4 个问题（见 `docs/评审记录/day5-代码评审.md`）。

## 最重要的收获
**"测试全绿"不等于"测试有用"**。我一开始理解的测试就是"有断言、能跑过"，但手册那句 `assertNotNull` 点醒我：
弱断言是自欺欺人。于是我把每条规则都逼到"验证因果链"：
- 取消不只是改状态，还要验证**时段真的释放 + 冲突解除**；
- 新预约不只是数组 +1，还要验证**占用→冲突**；
- 并主动补"已过期/已取消不可取消"的边界反例。

## 评审帮我抓到的真问题
- **时区 bug**：`toISOString().slice(0,10)` 是 UTC，凌晨 0–8 点会错——这种 bug 自己不点破很难发现。
- **XSS**：用户输入直接 innerHTML，之前完全没意识到。这两个都是"功能看起来正常"下的暗雷。
- 评审时强制要求"不要客套"，输出质量明显高，和"夸夸式"AI 回答是两回事。

## 卡过什么
- `node --test tests/` 把目录当成入口报 MODULE_NOT_FOUND，改用无参 `node --test` 自动发现解决。
- 让测试能在 Node 加载浏览器脚本：用 `vm` 注入 localStorage、并把 `const Store` 显式挂到沙箱全局。
