# 数据字典 · 实验室设备预约系统

> 第 7 天「MCP 提效」任务产物：本项目线上用浏览器 localStorage 持久化（题库定位：单机演示，不接数据库），
> 为完成实验七 T2「给自己的 Trae 配一个 MySQL MCP，让 AI 根据现有表结构生成一份数据字典入库 docs/」，
> 先把四张逻辑表落成 MySQL 等价结构 [`schema.sql`](schema.sql) 作为"现有表结构"，
> 再由 AI 对照源码与 DDL 生成本字典，人工逐项校对。
> 键名前缀 `leq_` = Lab Equipment Booking。

## 1. 存储总览

| localStorage 键 | 逻辑表 | 内容 | 写入时机 |
| --- | --- | --- | --- |
| `leq_equipment` | equipment 设备表 | 设备台账（6 条种子） | 首次访问 `Store.init()` |
| `leq_bookings` | bookings 预约表 | 全部预约（含已取消） | 预约/取消/改期时 |
| `leq_stats` | stats 访问统计表 | PV 与表单提交计数 | 每次打开页面、每次成功提交 |
| `leq_ai_stats` | ai_usage AI 用量表 | AI 调用量与 token 累计 | 每次 AI 调用后（含失败） |

## 2. equipment 设备表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | string | PK，如 `e1` | 设备唯一标识 |
| name | string | 非空，≤50 字 | 设备名称，如「3D 打印机」 |
| icon | string | emoji | 卡片图标 |
| location | string | 非空 | 位置，如「工程训练中心 114-A」 |
| desc | string | 非空 | 参数描述，如「FDM 熔融沉积，最大 220×220×250mm」 |

## 3. bookings 预约表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | string | PK，如 `b1730000000000` | 预约唯一标识（前端 `Date.now()` 生成） |
| equipId | string | FK → equipment.id | 关联设备 |
| equipName | string | 非空 | 设备名称冗余存储（列表展示免关联） |
| date | string | `YYYY-MM-DD`，≥ 当天 | 预约日期（F4 日期校验） |
| slotId | string | FK → 时段常量 `s1..s5` | 时段标识 |
| slotLabel | string | 非空 | 时段展示文本，如「08:00 - 10:00」 |
| name | string | 非空，≤20 字 | 预约人姓名 |
| sid | string | 非空，≤20 字 | 学号（「我的预约」查询键） |
| purpose | string | 非空，≤100 字 | 用途说明 |
| createdAt | string | ISO 8601 | 提交时间 |
| status | string | `active` / `cancelled` | 状态；过期不落库，由 `isBookingExpired` 实时判定 |

**业务约束（冲突检测，题库“命门”）**：同一 `equipId + date + slotId` 只允许一条 `status=active` 记录，即这三列组合在有效预约内唯一（`Store.hasConflict` 强制执行）。

## 4. stats 访问统计表（单对象，非数组）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| pvTotal | number | 累计页面访问次数（每次打开 +1） |
| pvDaily | object | `{"2026-10-13": 3}` 当日 PV，看板取近 7 天 |
| formSubmits | number | 预约表单成功提交次数 |

## 5. ai_usage AI 用量表（单对象，C1 挑战）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| calls | number | 累计调用次数（含失败） |
| okCalls | number | 成功次数 |
| failCalls | number | 失败次数 |
| tokensIn | number | 累计输入 token（上游 usage 优先，缺失时按文本长度估算） |
| tokensOut | number | 累计输出 token |

估算成本 = `tokensIn/1000 × PRICES.in + tokensOut/1000 × PRICES.out`（单价常量在 `js/ai.js`，默认 doubao-pro 档示例价）。

## 7. 常用查询路径（代码对照）

| 场景 | 入口 | 遍历方式 |
| --- | --- | --- |
| 冲突检测 | `Store.hasConflict(equipId, date, slotId)` | 全表 `some`，过滤 active |
| 我的预约 | `getBookings().filter(sid).sort(date+slotId)` | 全表 filter |
| 某日占用 | `Store.occupiedSlots(equipId, date)` | 全表 forEach 收集 Set |
| 看板聚合 | `Store.getBookingSummary()` | 一次遍历得 byEquipment/bySlot |
| AI 上下文 | `buildAIContext()` | active 预约投影为精简 JSON |

> 后续若接后端：四张表可直接建为 MySQL 表，`bookings` 加唯一索引 `(equip_id, date, slot_id, status)` 的部分索引或应用层校验（当前规则在应用层）。
> MySQL 落地版（含唯一索引兜底与种子数据）见 [`schema.sql`](schema.sql)。

## 8. Trae MySQL MCP 配置步骤（实验七 T2 复现用）

> 课程口径（手册原文）：Trae 设置 → MCP → 从市场添加（如 MySQL），配好连接信息后，AI 能直接查表结构、跑只读 SQL。**首次使用只给只读权限账号。**

1. **准备 MySQL**：本机或 Docker 起一个 MySQL 8.x（`docker run --name leq-mysql -e MYSQL_ROOT_PASSWORD=你的密码 -p 3306:3306 -d mysql:8`），执行 `schema.sql` 建库建表。
2. **建只读账号**（安全底线：首次用只读权限账号）：
   ```sql
   CREATE USER 'leq_ro'@'%' IDENTIFIED BY '只读密码';
   GRANT SELECT ON lab_equipment_booking.* TO 'leq_ro'@'%';
   FLUSH PRIVILEGES;
   ```
3. **Trae 配 MCP**：设置 → MCP → 从市场添加 **MySQL**（缺 `uvx` 命令时按市场页提示装 uv），填写连接信息：
   ```json
   {
     "mcpServers": {
       "mysql": {
         "command": "uvx",
         "args": ["mysql-mcp-server"],
         "env": {
           "MYSQL_HOST": "127.0.0.1",
           "MYSQL_PORT": "3306",
           "MYSQL_USER": "leq_ro",
           "MYSQL_PASSWORD": "只读密码",
           "MYSQL_DATABASE": "lab_equipment_booking"
         }
       }
     }
   }
   ```
4. **让 AI 干活的提示词**（照此复现本字典的生成）：
   > 连接 MySQL MCP，读取 `lab_equipment_booking` 的全部表结构（SHOW CREATE TABLE / information_schema），
   > 对照仓库 `js/data.js`、`js/storage.js` 的业务规则，生成一份中文数据字典（每表：字段/类型/约束/说明 + 业务约束 + 常用查询路径），写入 `docs/数据字典.md`；不确定的字段含义先问我，不要猜。
5. **人工校对要点**：冲突唯一键口径（active 才参与唯一性）、`status` 语义（过期不落库、实时判定）、AI 用量表字段与 `js/ai.js` 的 `PRICES` 对应关系。

**本次生成记录**：`schema.sql`（吴辰枫手写 + AI 校对）→ AI 对照 DDL 与源码生成本字典 → 人工修正 3 处（冲突唯一索引口径、`desc` 保留字、时段常量表说明）。MCP 只读账号未入仓库（安全底线：连接信息只留在 Trae 本地配置）。
