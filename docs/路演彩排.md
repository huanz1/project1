# 路演彩排 · 第 9 天（3 分钟走场 + 互评挑刺分级）

> 按实验九 T2：人人 3 分钟走场，其余人每人必须提一条刺；当场决定砍/救。
> 本项目为单人仓库，按“第二个 AI 评审”方式自演自评：先走场，再列出**预判会被挑的刺**并分级处理。

## 一、3 分钟走场脚本（压缩自 docs/演示脚本.md）

| 时间 | 动作 | 关键台词 |
| --- | --- | --- |
| 0:00–0:20 | 开场 | “设备抢手、线下看不到占用——这个系统让预约在线化，冲突自动防。” |
| 0:20–0:50 | 设备预约页 | 6 台设备台账；点预约、选时段、提交成功 |
| 0:50–1:20 | 冲突拒绝（重点） | 同设备同日同时段再约 → 按钮禁用 + 提交也被拦；“双保险，规则进了测试。” |
| 1:20–1:50 | 占用总览 + 我的预约 | 矩阵看占用；改期→旧档释放；取消→立刻再约成功 |
| 1:50–2:30 | 数据看板 + AI 助手 | 三图 + CSV 导出；周报点名“哪台抢手哪台闲置”；自然语言问一句；**停 server 演示兜底文案** |
| 2:30–3:00 | 收尾 | “纯前端 + 零依赖 AI 代理；10 条测试全绿、CI 自动跑、线上可访问。” |

## 二、预判挑刺清单（自评 + AI 评审）与分级处理

| # | 刺（别人可能挑的点） | 级别 | 处理决定 |
| --- | --- | --- | --- |
| 1 | AI 功能现场依赖 Key/网络，万一挂了演示断 | **必修** | 演示前固定 3 个问题预演 + 90 秒录屏备份；脚本第 6 步把“停 server 看兜底”设计成**正式演示环节**，把依赖变卖点 |
| 2 | github.io 国内手机网络可能打不开 | **必修** | 备用：本地 `node server/server.js` 一份（手机同局域网可开）+ 录屏；彩排当天真机（手机）验一次 |
| 3 | 数据存在浏览器 localStorage，换设备空空如也 | 建议 | 演示固定设备；说明里写明“数据为本地演示性质”，不做后端（范围取舍已记录） |
| 4 | 周报质量取决于提示词，可能答得泛 | 建议 | 提示词限定四节结构 + “只依据给定数据”；演示前用固定数据跑 3 次取稳定稿 |
| 5 | 单页应用刷新后停留在当前 Tab | 建议 | 接受（演示从首页进，无感知）；记录为已知限制 |
| 6 | 无登录鉴权，谁都能改数据 | 建议 | PRD 非目标明确不做；题库本题定位单机演示，合理 |
| 7 | AI 代理没有单元测试 | 建议 | CI 已做语法检查；代理逻辑薄（转发+错误映射），真机联调三条路径覆盖；不引入测试框架（范围控制） |

## 三、当场决定

- **砍**：无（当前范围已是闭环最小集）。
- **救**：#1、#2 两条必修项在 Demo Day 前一天全部落实（录屏 + 本地副本 + 手机真机验证）。
- **彩排结论**：ready / not ready —— 彩排后由本人填写，报组长汇总。
